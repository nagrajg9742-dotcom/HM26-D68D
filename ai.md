# CivicTrack — AI Usage Disclosure

## 1. Purpose

This document explains how AI tools were used during the development of CivicTrack.

AI tools were used as development assistance for understanding, debugging, documentation, and implementation support.

The team reviewed, adapted, tested, and integrated the resulting work into the project.

---

## 2. AI-Assisted Development

AI assistance was used for activities such as:

- Understanding programming concepts
- Debugging backend and API issues
- Understanding PostgreSQL and database errors
- Reviewing API implementation
- Improving input validation
- Designing documentation structure
- Preparing testing procedures
- Explaining implementation decisions
- Reviewing edge cases and possible failure scenarios

AI-generated suggestions were not treated as automatically correct. The team verified the implementation through local testing and modified it where required.

---

## 3. Backend Development

AI assistance was used while working on backend areas including:

- Express.js API development
- PostgreSQL database integration
- Authentication and authorization
- Complaint validation
- Duplicate complaint detection
- Complaint status management
- Status history
- Evidence handling
- Assignment and escalation-related functionality
- API testing and debugging

The final implementation was reviewed and tested by the development team.

---

## 4. Runtime AI

The current CivicTrack risk mechanism is primarily a rule-based system.

It uses factors such as:

- Complaint age
- Inactivity
- Priority
- Complaint history
- Status information

The system uses these factors to identify complaints that may require attention.

This should not be described as a machine-learning model.

---

## 5. AI-Assisted Documentation

AI assistance was also used to help prepare and organize project documentation, including:

- Architecture documentation
- Constraint documentation
- Limitations
- Setup instructions
- Project explanations
- Presentation and demonstration material

The team reviewed the documentation and adapted it to match the actual project implementation.

---

## 6. Verification and Testing

AI assistance was used to suggest test cases and debugging approaches.

The team performed local testing of important backend functionality, including:

- Authentication
- Complaint creation
- Input validation
- Invalid location handling
- Duplicate complaint detection
- Inappropriate-text validation
- Complaint retrieval
- Status updates
- Evidence-related functionality
- Officer-related functionality

Only functionality that was verified against the project implementation should be presented as completed.

---

## 7. Human Review

The development team remained responsible for:

- Choosing the project architecture
- Making implementation decisions
- Reviewing AI-generated suggestions
- Modifying code where required
- Running tests
- Checking API responses
- Integrating the final implementation
- Preparing the final submission

AI tools were used as development assistance and not as a replacement for team review and testing.

---

## 8. Transparency

The team is disclosing AI assistance as part of the project documentation.

The purpose of this disclosure is to clearly distinguish AI-assisted development support from the team's own review, testing, integration, and final project decisions.
